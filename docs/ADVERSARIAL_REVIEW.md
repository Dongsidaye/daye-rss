# 对抗式审查

审查假设攻击者控制某个 RSS 源、网页正文或第三方服务，并试图让个人服务器泄露数据、产生费用或给出错误结论。

## 已在审查中修复：生产免验证登录

- 问题：早期示例环境文件显式启用了 `DEV_AUTH_BYPASS`，复制后用于 Docker 部署会暴露免验证登录接口。
- 触发：用户直接复制示例配置，并只修改邮箱和密钥后启动生产容器。
- 最坏后果：任何能访问服务的人都可取得个人账户会话，读取订阅、文章、模型配置并触发 AI 调用。
- 现成利用：直接请求 `/api/auth/dev`，无需验证码。
- 修复：示例文件不再显式启用；非生产开发环境仍默认启用；生产环境检测到该开关会拒绝启动，并有自动化回归测试。

## 1. DNS 重绑定绕过 SSRF 检查

- 问题：系统先解析域名确认是公网地址，再由 `fetch` 重新建立连接；两次解析之间仍存在时间差。
- 触发：用户添加攻击者控制的域名，该域名在验证后切换到内网地址。
- 最坏后果：攻击者借服务器请求内网服务或云元数据端点。
- 现成利用：DNS rebinding 和短 TTL 域名是成熟利用方式。
- 当前缓解：禁止非 HTTP(S)、非标准端口、内网/保留地址，并对每次重定向重新验证；个人部署还应通过主机防火墙禁止容器访问管理网段和元数据地址。
- 结论：存在残余风险，建议生产部署增加出站网络策略。

## 2. 间接提示词注入影响摘要和分析

- 问题：文章可以包含伪装成系统指令的文字，模型不一定始终遵守隔离提示。
- 触发：恶意网页要求模型忽略任务、隐藏事实或输出误导结论。
- 最坏后果：错误预警、遗漏风险或形成错误研究判断。
- 现成利用：网页间接提示词注入已有大量公开示例。
- 当前缓解：正文被明确标记为不可信资料；模型无法访问 API Key、数据库或任意工具；回答要求引用来源并区分事实与推测。
- 结论：无法只靠提示词彻底解决，重要判断必须核对原文和多来源证据。

## 3. 主机完全失陷后 API Key 可被解密

- 问题：数据库与解密密钥最终都存在同一台运行主机上，加密主要保护静态数据库泄露。
- 触发：攻击者取得容器环境变量、主机管理员权限或未加密备份。
- 最坏后果：AI、搜索、SMTP 或 Firebase 凭据被盗用，产生费用并泄露请求内容。
- 现成利用：环境变量窃取、备份外泄和容器逃逸均有成熟手法。
- 当前缓解：AES-256-GCM、日志脱敏、Key 不回显、弱生产 Secret 拒绝启动。
- 结论：应使用最小权限 Key、服务商预算上限、主机加固和定期轮换；高要求场景应接入外部密钥管理服务。

## 4. 远程图片和媒体造成隐私泄露

- 问题：文章图片由客户端直接加载，来源站点仍能看到客户端公网 IP 和请求时间。
- 触发：打开带追踪像素或唯一媒体 URL 的文章。
- 最坏后果：来源站点将订阅者身份、阅读时间与 IP 关联。
- 现成利用：追踪像素是通用且成熟的分析方式。
- 当前缓解：移除脚本与事件属性，图片使用 `no-referrer` 和延迟加载。
- 结论：IP 泄露仍存在；隐私优先时应增加“阻止远程图片”或服务器图片代理模式。

## 5. 无应用侧日限额意味着必须依靠供应商预算

- 问题：应用不设置人为的每日 AI 调用上限，也无法统一获知不同供应商的实时 Token 价格和账户余额。
- 触发：选择昂贵模型、导入大量来源、处理超长文章、提高并发，或反复生成摘要与分析。
- 最坏后果：模型账号在用户察觉之前产生超出预期的账单。
- 现成利用：恶意 Feed 可用大量长文章放大输入 Token。
- 当前缓解：文章输入截断、默认只批量生成标题和短摘要、全文翻译按打开文章触发、失败时退避并显示状态。
- 结论：必须在模型服务商控制台设置硬预算和限流；提高并发前要先确认套餐边界。

## 6. 单机 SQLite 与常驻任务的故障边界

- 问题：抓取、API 和定时任务运行在同一进程，长时间模型调用或磁盘故障可能影响所有能力。
- 触发：大量订阅同时到期、数据库所在磁盘写满、第三方接口长期超时。
- 最坏后果：简报延迟、抓取停滞或服务暂时不可用。
- 现成利用：资源耗尽和磁盘填满是常见拒绝服务方式。
- 当前缓解：响应大小、超时、串行抓取、WAL、容器健康检查和自动重启。
- 结论：个人规模可接受；订阅源显著增长时应拆分工作进程并加入任务队列。
