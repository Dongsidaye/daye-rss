# Android 本地版对抗式审查

以下审查假设攻击者控制 RSS 内容、模型响应，或能够接触设备。问题按最坏情况分析。

## 1. 恶意 Feed 通过远程图片追踪阅读行为

- 问题：清洗后的文章仍允许加载 HTTPS 图片，图片服务器能看到手机公网 IP 和请求时间。
- 触发：用户打开包含唯一图片 URL 或追踪像素的文章。
- 最坏后果：发布者把用户身份、订阅关系、阅读时间和 IP 关联起来。
- 现成利用方式：一像素追踪图、每订阅者唯一 URL 和常规 CDN 访问日志都能实现。
- 当前缓解：移除脚本、事件属性和 iframe，图片使用 `no-referrer`；IP 暴露仍然存在。

## 2. DNS 重绑定尝试访问局域网

- 问题：JavaScript 能检查域名和字面 IP，但无法把 Android 原生请求固定到检查过的公网 IP。
- 触发：用户订阅攻击者控制的 HTTPS 域名，攻击者在请求时改变 DNS 解析结果。
- 最坏后果：手机可能尝试连接路由器、NAS 或其他内网服务。
- 现成利用方式：DNS rebinding 与短 TTL 域名是成熟技术；HTTPS 证书校验会阻止多数利用，但不能视为绝对隔离。
- 当前缓解：仅允许 HTTPS、80/443 标准端口，拒绝 localhost、私网、链路本地和保留字面地址，并复核最终重定向 URL。

## 3. 文章提示词注入影响摘要和研究判断

- 问题：恶意文章可以把“忽略规则、隐藏风险”等内容伪装成正文，诱导模型输出错误结论。
- 触发：对攻击者控制的文章生成摘要、翻译或跨文章问答。
- 最坏后果：遗漏关键信息、形成错误投资判断或错误监控结论。
- 现成利用方式：网页间接提示词注入已有大量公开样例，不依赖代码执行。
- 当前缓解：系统提示明确将资料标为不可信，模型没有工具权限，输入长度受限；重要结论仍必须核对原文。

## 4. 调试签名、Root 或恶意辅助功能导致设备数据泄露

- 问题：Keystore 能保护静态密钥，但无法保护已解锁设备上的屏幕、剪贴板和运行时明文。
- 触发：手机 Root、安装恶意辅助功能/录屏软件、开启调试后把设备交给攻击者，或系统本身失陷。
- 最坏后果：RSS 资料、研究记录和模型 API Key 被窃取并产生费用。
- 现成利用方式：恶意 Accessibility Service、Frida/Root Hook、屏幕录制和调试注入均为成熟手法。
- 当前缓解：禁用 Android 备份、Key 不进入 Web 数据库、Keystore 密钥不可导出；应给手机设置强锁屏并只从可信位置安装 APK。

## 5. 恶意或异常 Feed 耗尽存储和流量

- 问题：大量长文章、图片或频繁刷新可能消耗手机空间、电量和流量。
- 触发：订阅高频 Feed，或 Feed 故意返回接近大小上限的内容。
- 最坏后果：App 变慢、移动数据超额、手机存储紧张甚至系统回收 App 数据。
- 现成利用方式：RSS 压缩炸弹、超长 description 和高频 GUID 变化都可以扩大资源使用。
- 当前缓解：单响应限制 5 MB、每源单次最多 100 篇、文章库最多 600 篇、单篇清洗正文最多 300,000 字符，并串行刷新来源。

## 6. AI 调用次数不等于费用上限

- 问题：手机本地版无法统一获知所有供应商、模型和 Token 的实时价格。
- 触发：长文章摘要、全库问答、反复生成简报，或选择昂贵模型。
- 最坏后果：模型账号产生超出预期的费用。
- 现成利用方式：诱导用户反复点击、恶意 Feed 放入超长文本，或使用被盗的设备直接发起调用。
- 当前缓解：模型输入截断到 45,000 字符，Key 存在 Keystore；必须同时在模型供应商控制台设置硬预算和限额。
